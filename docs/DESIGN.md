# PhysiSim 개발·디자인 철학

> 한 문장: **본질만 남긴다.** 더할 것이 없을 때가 아니라 뺄 것이 없을 때 완성이다.
> 이 문서는 원칙만 다룬다. 색상값·간격·컴포넌트 같은 구체 값은 코드(디자인 토큰, `apps/web`)가 기준이다.

## 1. 개발 철학 — 핵심만, 제1원리로

PhysiSim은 "모든 걸 갖춘 시뮬레이터"가 아니라 **핵심이 정확히 동작하는 시뮬레이터**를 만든다.

1. **요구사항부터 의심한다.** 모든 기능은 "이게 없으면 핵심 목표(Model → 구성 → 시뮬레이션 → 분석)가 깨지는가?"를 통과해야 한다.
2. **지운다.** 가장 좋은 부품은 없는 부품이다. 코드·옵션·설정·의존성은 필요가 증명될 때만 추가한다. 다시 넣는 일이 가끔 생기지 않는다면 충분히 지우지 않은 것이다.
3. **단순하게 만든다.** 지울 수 없는 것만 단순화한다. 불필요한 것을 최적화하지 않는다.
4. **빠르게 돈다.** 작은 단위로 만들고, 테스트하고, 커밋한다. 피드백 루프를 짧게 유지한다.
5. **자동화는 마지막.** 손으로 반복해 본 뒤에 자동화한다.

실천 규칙

- 추상화는 세 번째 반복에서 만든다. 두 번째까지는 복붙이 낫다.
- 설정 옵션보다 좋은 기본값 하나.
- 의존성 하나를 추가하는 비용은 "그 라이브러리 전체를 이해하고 유지할 책임"이다.
- 모르는 것은 추측하지 말고 측정한다. 물리는 근사여도 근사의 한계를 숨기지 않는다.

## 2. UI 철학 — 미니멀, 모던, 캔버스가 주인공

PhysiSim의 화면에서 주인공은 **사용자가 만든 시스템**이다. UI는 그 시스템을 가리지 않도록 물러나 있는다.

### 2.1 원칙

| 원칙 | 의미 |
|---|---|
| **Canvas first** | 화면 전체가 작업 공간이다. 고정 패널·툴바·메뉴바를 두지 않고, 컨트롤은 캔버스 위에 가볍게 떠 있다. |
| **Calm by default** | 기본 상태는 조용하다. 밝은 중성 회색 공간, 흐린 그리드, 흰색·그래파이트 객체. 소음이 없어야 신호가 보인다. |
| **One accent = energy** | 강조색은 단 하나. 그 색은 **살아 있는 것**에만 쓴다 — 전류가 흐르는 배선, 동작 중인 관절, 선택된 객체. 색이 곧 시뮬레이션 상태다. |
| **Line clarity** | 사실적 렌더링보다 명료한 형태. 얇은 외곽선과 평평한 음영으로 구조를 읽히게 한다. |
| **Progressive disclosure** | 필요할 때만 나타난다. 속성 인스펙터는 선택 시에만, 고급 옵션은 한 단계 안쪽에. |
| **Few, labeled, round** | 도구는 적게, 아이콘에는 짧은 라벨, 부드러운 원형·라운드 형태. 비활성 상태는 지우지 않고 흐리게. |
| **Direct manipulation** | 대화상자보다 캔버스 위에서 바로 끌고, 잇고, 돌린다. |
| **Motion with purpose** | 애니메이션은 상태 변화를 설명할 때만, 짧게. 장식용 모션은 없다. |

### 2.2 하지 않는 것

- 대시보드처럼 패널이 화면을 나눠 먹는 레이아웃
- 여러 강조색, 그라디언트, 그림자 남용, 장식 아이콘
- 같은 정보를 두 곳에 보여주기
- 확인 대화상자 남발 (대신 되돌리기를 제공)

### 2.3 시각 언어 (방향만, 값은 토큰으로)

- **배경**: 차갑고 밝은 중성 회색 + 원근 그리드. 다크 모드는 같은 구조를 반전.
- **객체**: 흰색 / 그래파이트 2톤 + 얇은 검은 외곽선.
- **강조**: 단일 액센트 1색 (구체 색은 Phase 5에서 토큰으로 결정).
- **타이포**: 산세리프 한 패밀리, 2~3개 굵기.
- **컨트롤**: 반투명 원형 버튼 + 라벨, 화면 가장자리에 기능별로 묶어 배치.

## 3. 참고 무드

벤치마크 CAD 앱 스크린샷(밝은 그리드 캔버스, 떠 있는 원형 도구, 2톤 라인 렌더링, 단일 오렌지 포인트)의 **느낌만** 참고했다.
레이아웃·아이콘·배치를 그대로 복제하지 않는다. 특정 제품의 디자인을 복제하지 않는다는 원칙은 `AGENTS.md` §4를 따른다.
