# 시나리오: Wearable Camera Node

> 중간 목표(마일스톤). 시뮬레이터로 아래 케이스를 하나씩 구현·검증한다. **구현 가능성이 생기는 대로** 가져가며, 지금 안 되는 것은 필요한 능력(Capability)으로 쪼개 Phase 계획에 올린다.

## 제품

버튼을 눌러 특정 물체·장면을 촬영하고, 이미지를 무선으로 스마트폰 또는 서버에 보내는 초소형 독립형 카메라. 클립·자석·펜던트·모듈형. 소형 충전식 배터리. AI 처리는 스마트폰/서버.
핵심 목표: 최소 크기·비용, 높은 화질, 낮은 소비전력. 자체 PCB.

## 케이스

| 케이스 | 구성 | 특징 |
|---|---|---|
| **A 통합형** | ESP32-S3 + OV2640/OV5640 + PSRAM + Wi-Fi + 배터리/전원관리 | 저렴·간단, 초기 프로토타입. 메모리·영상 처리 제약 |
| **B 카메라 SoC형** | 센서 + 카메라 SoC(ISP, JPEG) + Wi-Fi | 화질 최적화 유리, SDK 난이도 |
| **C 분리형** | 카메라 모듈 + FPC + 메인보드(MCU/SoC, Wi-Fi) + 배터리 | 크기·배치 자유, FPC 설계 추가. **최종 제품 구조** |
| **D 독립 네트워크형** | 센서 + MCU/SoC + Wi-Fi/LTE + 안테나 | 스마트폰 없이 서버 직접 전송, 전력·비용 증가 |

Case A 세부: A-1 ESP32-S3-EYE 일체형(기능 검증) · A-2 ESP32-S3 + OV2640(저비용) · A-3 + OV5640(화질 비교) · A-4 커스텀 PCB(최종 크기 최적화).

## 공통 동작 흐름

버튼 → 절전에서 깨어남 → 카메라 활성화 → 촬영 → JPEG → 무선 전송 → 절전 복귀.

## 개발 방향

초기 프로토타입 A-1 → 최종 C → 확장 B 또는 D. 비교 지표: **소비전력(전송 1회당 에너지, 배터리 수명), 촬영→전송 지연, 크기·BOM**.

## 시뮬레이터에 필요한 능력 (Phase 계획의 근거)

| 필요 | 지금 | 비고 |
|---|---|---|
| 버튼 입력 | 있음 (P6-T1) | 깨우기 인터럽트는 별도 |
| ESP32-S3 | 없음 | avr8js는 AVR 전용. Xtensa 에뮬레이션은 큼 → **동작 모델(Behavior)로 추상화**하거나 QEMU 검토 (결정 게이트) |
| 카메라 센서(OV2640/5640) | 없음 | 촬영 이벤트·해상도·프레임 크기·전류 프로파일 모델 |
| 절전 상태·전력 상태머신 | 없음 | 상태별 전류(딥슬립 µA ~ Wi-Fi TX 수백 mA) |
| 배터리·충전·전원관리 | 없음 | 용량·내부저항·전압 강하, 에너지 적분 |
| Wi-Fi/네트워크 | 없음 | 연결·전송 시간·전류, 대역폭 |
| 스마트폰/서버 | 없음 | 수신 이벤트 기록, 지연 측정 (Agent 보조) |
| FPC·분리형 | Port 연결로 표현 가능 | 신호 길이·손실은 후순위 |
| 계측: 에너지·지연 | trace 있음 | 에너지(mAh)·수명 계산 |
